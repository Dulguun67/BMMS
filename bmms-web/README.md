# БММС веб интерфейс

Бүлгийн менежментийн мэдээллийн системийн React frontend (React 19, React Router 7, Vite 8). `bmms-api`-тай холбогдож ажиллана. Дизайн нь дипломын V бүлгийн UI зохиомжийг (Wonders брэнд, Зураг 5.1-ийн өнгөний палитр) дагасан.

## Хөгжүүлэлт

```bash
npm ci
# bmms-api-г http://localhost:8080 дээр ажиллуулсан байна
npm run dev          # http://localhost:5173  (/api хүсэлтийг 8080 руу proxy хийнэ)
npm run build        # dist/
```

Локал орчинд API-г `COOKIE_SECURE=false` тохиргоотойгоор ажиллуулна, учир нь http дээр Secure cookie хадгалагддаггүй.

## Бүтэц

| Хавтас | Агуулга |
| --- | --- |
| `src/api` | `client.js`: токен удирдлага, автомат refresh. `hooks.js`: `useApi`, `useAction` |
| `src/auth` | Нэвтрэлт, хэрэглэгч, сонгосон бүлгийн context |
| `src/components` | Layout, Modal, Toast, график, UI элементүүд |
| `src/pages` | Нүүр, Бүртгэл, Анги танхим, Үнэлгээ, Төлөвлөгөө, Тайлан, Ганцаарчилсан, Хэрэглэгч, Тохиргоо |
| `e2e` | jsdom дээр суурилсан E2E тест |
| `deploy` | S3 + CloudFront байршуулах скрипт, SPA чиглүүлэх функц |

## CSV-ээс хүүхэд оруулах

Бүртгэл → «CSV-ээс оруулах» цонхоор олон хүүхдийг нэг дор бүртгэнэ:
1. «Загвар татах» товчоор загвар файлыг татна.
2. Excel-ээр бөглөөд **CSV UTF-8** хэлбэрээр хадгална.
3. Файлаа сонгоно. Систем мөр бүрийг урьдчилан харуулна.
4. «Шалгах» дарахад сервер мөр, талбар бүрийн алдааг заана.
5. Бүх мөр зөв болсны дараа «Оруулах» дарна.

Нэмэлт мэдээлэл:
- Огноог `2021-03-15`, `2021.03.15`, `15.03.2021` хэлбэрээр оруулж болно.
- Хүйсийг «эрэгтэй/эмэгтэй» гэж бичиж болно.
- Windows-1251 кодчилолтой файлд «Ө», «Ү» үсэг алдагддаг тул систем анхааруулга өгнө.

## Эрхээр ялгагдах интерфейс

- **Бүлгийн багш:** өөрийн бүлгийн бүх модулийг бөглөнө, төлөвлөгөө, тайлангаа илгээнэ.
- **Заах арга зүйч:** цэцэрлэгийн бүх бүлгийг зөвхөн уншина. Дээд хэсгээс бүлэг сонгоно. Цэсэнд батлах хүлээгдэж буй зүйлсийн тоо харагдана. Төлөвлөгөө, тайланг батална эсвэл буцаана (буцаахдаа шалтгаан заавал бичнэ). Хоолны төлбөр, амралтын өдөр, хяналтын асуулт, бүлэг, үнэлгээний үеийг тохируулна.
- **Систем хариуцагч:** зөвхөн Тохиргоо хэсгийг харна: хэрэглэгч, цэцэрлэг, хичээлийн жил, бүлэг, улсын баяр. Хүүхдийн мэдээлэл харагдахгүй.

Эрхийг API бүх хүсэлт дээр дахин шалгадаг. Интерфейс дэх хязгаарлалт нь зөвхөн хэрэглэхэд хялбар болгох зорилготой.

## Нэвтрэлтийн шийдэл

- **Хоёр алхамтай нэвтрэлт.** MFA идэвхтэй хэрэглэгчээс нууц үгийн дараа Authenticator апп-ын код эсвэл нэг удаагийн нөөц код асууна.
- **Нэвтэрсний дараах заавал алхам.** Түр нууц үгтэй хэрэглэгч эхлээд нууц үгээ солино. MFA заавал боловч тохируулаагүй хэрэглэгч (арга зүйч, admin) QR кодоор MFA тохируулж, нөөц кодоо хадгална. Эдгээрийг хийх хүртэл систем рүү нэвтрэхгүй.
- **Нууц үгээ мартсан.** Нэвтрэх хуудаснаас имэйл оруулахад холбоос ирнэ. Холбоос `/nuuts-ug-sergeeh#token=…` хэлбэртэй бөгөөд хуудас токеныг уншмагц хаягаас арилгана. MFA идэвхтэй хэрэглэгчээс апп-ын кодыг мөн асууна.
- **QR код.** `qrcode` сангаар хөтөч дотор үүсгэдэг тул нууц түлхүүр гадны сервис рүү явахгүй.
- **Хэрэглэгч хуудас.** Багш MFA-г сайн дураар асааж, унтрааж болно. Хэрэглэгч бүр нөөц кодоо шинэчилж болно.

- **Access token.** Зөвхөн санах ойд хадгалагдана (localStorage-д биш), тиймээс хуудсыг хаахад устана.
- **Refresh token.** API-ийн `HttpOnly; Secure; SameSite=Strict` cookie-д хадгалагдана. Хуудас дахин ачаалахад `/auth/refresh`-ээр сессийг сэргээнэ.
- **401 хариу.** Нэг удаа refresh хийгээд хүсэлтийг давтана. Зэрэгцээ ирсэн хүсэлтүүд нэг refresh-ийг хүлээнэ. Refresh амжилтгүй бол нэвтрэх хуудас руу шилжинэ.

## AWS дээр байршуулах (S3 + CloudFront)

Frontend ба API-г **нэг домэйноос** үйлчилнэ. Ингэснээр CORS шаардлагагүй болж, refresh cookie SameSite=Strict хэвээр ажиллана.

| CloudFront behavior | Origin | Тохиргоо |
| --- | --- | --- |
| `/api/*` | ALB (bmms-api) | CachingDisabled, AllViewerExceptHostHeader origin request policy, бүх HTTP method, HTTPS only |
| Default (`*`) | S3 (хаалттай, Origin Access Control) | CachingOptimized, `deploy/cloudfront-spa-rewrite.js` функц (viewer request), response headers policy |

**SPA fallback.** Distribution-ий custom error response (403/404 → index.html) **ашиглахгүй**. Тэр тохиргоо `/api/*`-ийн алдааны хариуг ч index.html болгож хувиргана. Оронд нь CloudFront Function ашиглана.

**Response headers policy.** HSTS, `X-Content-Type-Options`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY` болон дараах CSP-г тохируулна:

```
default-src 'self'; script-src 'self'; style-src 'self' https://fonts.googleapis.com;
font-src https://fonts.gstatic.com; img-src 'self' data:; connect-src 'self';
frame-ancestors 'none'; base-uri 'self'; form-action 'self'; object-src 'none'
```

Google Fonts-ыг өөрийн S3-д хадгалбал CSP-ээс гадны хоёр домэйныг хасаж болно.

**Байршуулах:**
```bash
BUCKET=<s3-bucket> DISTRIBUTION_ID=<cloudfront-id> ./deploy/deploy.sh
```

**API-ийн тохиргоо.** `CORS_ORIGINS=https://<домэйн>` (production-д заавал) болон `COOKIE_SECURE=true` гэж тохируулна.

**API-г тусдаа домэйнд байршуулах бол.** Хоёр домэйн ижил үндсэн домэйнтэй байх ёстой (жишээ нь, `app.x.mn` ба `api.x.mn`), эс тэгвээс SameSite=Strict cookie илгээгдэхгүй. Энэ тохиолдолд `VITE_API_BASE`-г зааж build хийнэ.

## Тест

`e2e/e2e.cjs` нь бүтээгдсэн аппыг jsdom дээр ажиллуулж, бодит API болон `05_demo_data` ачаалсан MySQL-тэй холбогдоно. Нийт 49 шалгалт хийнэ:
- **Хуудас бүр:** алдаагүй ачаалж буй эсэх.
- **Багшийн үйлдлүүд:** ирц, хүүхэд нэмэх, рубрик үнэлгээ, төлөвлөгөө үүсгэж илгээх, ганцаарчилсан сургалт.
- **Сесс:** хуудас дахин ачаалахад сэргэх, гарах.
- **Арга зүйчийн эрх:** ирцийг зөвхөн унших, шалтгаангүй буцаахыг хориглох, батлах.
- **Admin-ий эрх:** хүүхдийн цэс харагдахгүй байх.
- **CSV оруулах:** алдаатай мөрийг тэмдэглэх, засаад бүртгэх.
- **Нэвтрэлтийн хамгаалалт:** admin-ий MFA-г QR-ээр тохируулах, нөөц кодоор нэвтрэх, шинэ хэрэглэгч түр нууц үгээ заавал солих, имэйлийн холбоосоор нууц үг сэргээх.

```bash
# API-г MFA_REQUIRED_ROLES=admin MAIL_PROVIDER=console тохиргоотой ажиллуулж, stdout-ийг файлд бичнэ
API=http://127.0.0.1:8080 API_LOG=<API-ийн лог файл> E2E_PASSWORD=<demo хэрэглэгчдийн нууц үг> npm run test:e2e
```

Тестийн өмнө demo хэрэглэгч `nomin@demo.mn`, `oyunaa@demo.mn` болон `admin@demo.mn`-д `E2E_PASSWORD` нууц үгийг тохируулна. Тест өгөгдөл өөрчилдөг тул ажиллуулах бүрд шинэ DB ачаална.
